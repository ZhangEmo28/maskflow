# MaskFlow 修改记录

## 2026-10-19 阶段 3：AI 能力

- **按标签自动识别（SAM 3 文本提示）**：新增“AI 方式”选择。“按标签识别”把项目所有标签作为 SAM 3 文本提示一次推理，每个 mask 直接带上对应类别和置信度；同一目标命中多个提示时保留得分更高的一个（框 IoU ≥ 0.85）。每个标签可设置英文提示词（如 安全帽 → hard hat），存于新表 `project_label_prompts`；标签删除时一并清理，复制项目时一并复制。存在没有英文提示词的中文标签时，默认仍用“分割一切”，并提示补充提示词。SAM 服务新增 `POST /api/annotation/concepts`。
- **后台批量标注**：“批量运行 AI”改为调用 `POST /api/annotations/batch`，由服务器后台任务逐张处理（与交互请求共享 GPU 并发槽），进度、成功/失败数和最近错误写在任务记录里，前端显示进度条并可取消；关掉页面不中断，API 重启后从已处理位置继续。同一项目同时只允许一个批量任务；配额用完、推理服务不可用或项目/模型失效时整体中止，单张图片失败则跳过继续。批量任务不再为每张图片单独生成任务记录。
- **自定义 YOLO 模型预标注**：可上传 ONNX 格式的 YOLO 模型（新表 `ai_models`，计入存储配额，记录 SHA-256），选择“自定义模型”即可用它单张或批量预标注；模型类别名与项目标签按名称（不区分大小写）对应，未对应的类别保留为未分配，供人工处理。推理服务按需从 API 获取模型并校验哈希后缓存。出于安全考虑不接受 `.pt`：PyTorch 检查点是 pickle，加载时会执行任意代码；ONNX 只含数据，可用 `yolo export model=best.pt format=onnx` 导出。SAM 服务新增 `/api/yolo/models/{id}`（查询/上传/删除缓存）与 `POST /api/yolo/predict`，Docker 依赖新增 `onnxruntime-gpu`。
- **复核排序（主动学习）**：图片列表接口返回每张图的待复核数与最低置信度；队列新增“待复核”筛选和“低置信度优先”排序，上一张/下一张按当前队列顺序切换。
- 验证：后端 91 项测试（新增解析、提示词、批量完成/取消/续跑/服务中断、模型上传一次与类别对应、拒绝 `.pt` 等）与 MySQL 集成测试通过；SAM 服务新增 9 项接口测试（用替身模型，无需 GPU）并加入 CI；前端单元测试与构建通过。另用“替身模型 + 真实 SAM 服务代码”在浏览器中实测：按标签识别、提示词保存、后台批量进度、上传模型后预标注与类别回显、已确认目标保留、复核排序与筛选均符合预期。真实 SAM 3 / YOLO 推理效果需在 GPU 环境验证。

## 2026-10-19 阶段 1：持久化地基

- **增量写库**：此前每次写操作都会对所有表的每一行执行一次 upsert，再执行一次全表 `DELETE … NOT IN`，数据越多越慢。现在仓储只写入与上一次已提交快照相比新增、变化或删除的行；每批最多 200 行合并成一条多行 upsert（MySQL 8.0.19+ 行别名语法），删除按主键批量执行。启动时的旧版 JSON 状态迁移仍一次性全量写入。
- **读写隔离**：写操作在私有的浅拷贝快照上修改（行对象不可变，共享引用，只复制集合），数据库提交成功后才原子发布。其他请求永远只读到已提交的快照，不会再遇到“集合已修改”异常或读到会被回滚的数据。不再在每次写入时对整个状态做 JSON 深拷贝。
- **会话令牌哈希存储**：数据库只保存会话令牌的 SHA-256；旧的明文会话在启动时就地转换，已登录用户不受影响。
- **长耗时 I/O 移出写锁**：数据集导出（打包 zip、上传 MinIO）和项目复制（复制对象）改为在锁外基于已提交快照执行，只把最后登记记录放进写锁；失败时清理已生成的文件。
- **日志**：业务 4xx 不再记为错误日志，真正的 5xx 由统一异常处理记录完整异常。
- **CI**：后端测试增加 MySQL 8.4 服务容器，运行真实数据库集成测试；前端 CI 增加 `npm test`。
- 验证：后端 82 项测试通过，含连续 6 次全量运行稳定，以及在本机临时 MySQL 9.6 上的集成测试（450 个文件逐个写入、标签重排、删除后重新加载一致）。用临时 MySQL 启动 API 做了冒烟测试：注册、找回密码不回显、业务错误 JSON、`X-Forwarded-For` 下按真实 IP 限流均符合预期。

## 2026-10-19 阶段 0：安全与数据正确性修复

- **找回密码不再回显重置码**：此前 Development 或 `MASKFLOW_PASSWORD_RESET_INLINE=true` 时接口直接返回重置码，知道邮箱即可接管账号。现在重置码只在 Development 环境打印到 API 日志，`MASKFLOW_PASSWORD_RESET_INLINE` 已移除；前端提交邮箱后直接进入“输入重置码”步骤。
- **反向代理真实 IP**：启用 ForwardedHeaders（`MASKFLOW_TRUSTED_PROXIES` 可配置，默认信任回环与私有网段），登录限流按“IP+邮箱”与“单 IP”两级计数，不再能通过 nginx 后的同一 IP 锁死任意账号；限流表定期清理。
- **登录不再写库**：密码校验移到全局写锁之外，登录失败不触发数据库写入；注册/改密的 PBKDF2 计算也移出写锁。不存在的邮箱同样消耗一次哈希时间，避免按响应时间枚举邮箱。
- **改密码竞态**：改密码时在写锁内重新读取用户，避免并发上传等修改导致出现重复用户记录。
- **统一错误响应**：新增全局异常处理，业务错误（配额、导出校验、项目不存在等）按原状态码返回 `{ detail }`，其他异常返回通用提示，不再泄露堆栈。
- **AI 框不再加边距**：SAM 返回的 `yoloBox` 改为贴合 mask 的真实外接框（此前每边加 `max(8px, 长边 1.2%)`，导致检测训练标签系统性偏大）；前端改为把框线画在框外侧，显示效果不变。
- **自动标注选最大轮廓并带置信度**：mask 有多段轮廓时取面积最大的一段（与前端点提示一致）；每个目标记录 SAM 置信度；目标 id 重新生成，避免多次运行重复。
- **重新运行 AI 保留已确认目标**：自动标注只替换未确认的 AI 结果，已人工确认的目标保留，与其高度重叠（IoU ≥ 0.7）的新结果视为重复丢弃。“批量运行 AI”默认只处理未标注图片，全部已标注时需确认后才重跑；当前图有未保存修改时运行前会提示。
- **分类裁剪导出处理 EXIF 方向**：图像处理由 ImageSharp 3.1.12（存在已公开漏洞，修复版 4.x 需商业许可证）换为 MIT 许可的 SkiaSharp，解码时按 EXIF 方向旋转，与浏览器和 SAM 坐标一致；限制单图最大像素数；透明区域裁剪后铺白底。
- **对象存储与数据库一致**：删除文件/项目时，存储对象在数据库提交成功后才删除；数据库写入失败时清理本次新写入的上传、复制和导出文件。MinIO 改为共享客户端、流式读取（不再把整个对象读进内存），复制项目使用服务端复制。
- **配额读取无副作用**：查询配额不再修改共享状态或写库，跨天/换套餐的额度在实际消耗时才落库。
- **幽灵 Job**：任务对应的 Job 状态与任务同步（完成即 `succeeded`），启动时修正历史数据；节点只领取已审批、同资源池的排队任务。
- **其他**：zip 内文件/目录名过滤 `..` 和各平台非法字符；SAM 服务图片解码移出事件循环、置信度参数在推理锁内设置；docker-compose 的环境回退值改为 Production、计费开发模式回退为关闭；nginx 增加基础安全响应头；README 仓库地址改为 ZhangEmo28/maskflow；vite 相关依赖移至 devDependencies。
- 保留 2026-09-18 约定的“点击保存即确认已分配类别的目标”规则不变。
- 验证：后端 72 项测试（新增自动标注合并、限流、可信代理、异常处理、存储一致性、节点领取、EXIF 旋转裁剪等测试）与 Release 构建通过，`dotnet list package --vulnerable` 无漏洞；前端 3 项单元测试与生产构建通过；SAM 服务通过语法编译检查。本机无 GPU/Docker，SAM 推理与浏览器回归脚本未运行。

## 2026-09-07 数据集分层随机划分

- 检测、分割和分类裁剪导出统一采用按原图分组的多标签分层随机划分，替代按上传顺序或裁剪顺序切分。
- 先统计每类的原图数与标注目标数，优先分配稀有类别，并兼顾目标数量和整体图片比例；背景图片按剩余图片配额分配。
- 同一原图及其全部分类裁剪始终属于一个集合，避免同源裁剪跨训练、验证、测试集。暂不识别不同文件之间的近重复图片或同一拍摄对象。
- 保留用户配置比例与默认 70/20/10。类别样本充足时尽量覆盖三个集合；不足时优先训练集，其次验证集，并在报告中提示缺样。多标签共现与原图不可拆分时，实际比例可能偏离目标比例，不保证固定比例能获得最佳泛化效果。
- 导出接口新增可选 Seed 参数，默认 42；数据、比例与种子相同时划分可复现，修改种子可重新随机划分。
- ZIP 新增 split-report.json，记录每类目标数、图片数、各集合分布、原图分配清单及类别缺样提示。
- 按导出最终类别表重新映射 ClassId，修复跨项目类别编号冲突；data.yaml 类别名使用安全引号输出。
- 校验各集合比例必须在 0 到 100 之间且总和为 100；增加分层算法及三种格式实际 ZIP 导出回归测试。
